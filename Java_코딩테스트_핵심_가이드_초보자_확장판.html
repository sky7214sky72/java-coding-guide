코테 입문과 문제 풀이

공식보다 먼저, 문제를 어떻게 읽고 작은 예제로 검증할지부터 익힌다.

먼저 알아둘 것: 코딩 테스트는 수학 시험이 아니다

코딩 테스트는 어려운 공식을 많이 아는 사람이 무조건 이기는 시험이 아니야. 대부분은 문제를 작은 단계로 나누고, 같은 계산을 반복하지 않게 만들고, 그 과정을 Java로 정확히 옮기는 능력을 보는 거야.

수학을 오래전에 배웠다면 공식을 외우기 전에 숫자 몇 개를 직접 써서 규칙을 발견하는 방식으로 배우면 돼. 아래 설명은 “정의부터 외우기”가 아니라 “예시를 보고 이유를 이해한 뒤, 짧은 코드 패턴을 외우기” 순서로 되어 있어.

코드 블록은 알고리즘의 핵심을 설명하는 학습용 예제야. 일부는 클래스·main·import·입력 처리 등을 생략했으므로, 그대로 붙여 넣어 실행하는 완성 프로그램이 아닐 수 있어.

문제 풀이의 6단계

  1. 입력과 출력 찾기: 무엇을 받으며, 최종적으로 무엇을 반환해야 하는지 한 문장으로 적는다.
  2. 예제를 손으로 풀기: 코드부터 쓰지 말고 예제의 중간 결과를 종이에 적는다.
  3. 가장 단순한 방법 떠올리기: 모든 경우를 하나씩 확인한다면 어떻게 할지 먼저 생각한다.
  4. 느린 부분 찾기: 같은 값을 계속 다시 계산하는지, 불필요하게 모든 쌍을 비교하는지 본다.
  5. 알고리즘 패턴 고르기: 정렬, 해시, 투 포인터, 스택, BFS, DP 중 어떤 도구가 맞는지 정한다.
  6. 작은 예제로 검산하기: 빈 입력, 원소 한 개, 중복 값, 최솟값·최댓값을 확인한다.

시간 복잡도는 “입력이 커졌을 때 얼마나 일이 늘어날까?”

n은 보통 데이터 개수야. 예를 들어 배열에 숫자가 10개 있으면 n=10이라고 쓰는 거지. 정확한 초를 계산하기보다 데이터가 커질 때 일이 얼마나 빠르게 늘어나는지 비교해.

O(1)데이터가 커져도 작업 수가 거의 일정배열의 arr[3] 읽기
O(log n)범위를 매번 절반으로 줄임정렬된 배열 이분 탐색
O(n)데이터를 한 번씩 확인배열 전체 합 구하기
O(n log n)정렬에서 흔히 만나는 수준Arrays.sort()
O(n²)각 원소마다 전체를 다시 확인모든 두 원소 쌍 비교

예를 들어 숫자 1,000개를 한 번씩 확인하면 대략 1,000번이지만, 이중 반복문은 대략 1,000×1,000=1,000,000번까지 갈 수 있어. 이 차이를 줄이는 것이 알고리즘 공부의 큰 목표야.

반복문을 처음부터 읽는 법

배열의 합을 구하는 코드
int sum = 0;
for (int i = 0; i < arr.length; i++) {
    sum += arr[i];
}

sum = 0은 누적할 그릇을 비우는 거야. i = 0은 첫 번째 칸부터 시작한다는 뜻이고, i < arr.length는 배열의 마지막 칸까지 확인하겠다는 뜻이야. sum += arr[i]는 기존 sum에 현재 칸의 숫자를 더해 다시 sum에 넣으라는 의미야.

현재 iarr[i]더한 뒤 sum
040 + 4 = 4
174 + 7 = 11
2211 + 2 = 13

반복문이 헷갈릴 때는 머릿속으로 한 번에 이해하려고 하지 말고, i, 현재 값, 변수 값을 표로 적어. 이 습관이 투 포인터·BFS·DP를 이해할 때도 그대로 쓰인다.

하루 공부 방법: 복사해서 끝내지 않기

  1. 5분 — 문제를 읽고 요구사항을 말로 바꾸기. “배열에서 조건을 만족하는 구간을 찾는다”처럼 적는다.
  2. 10분 — 예제를 손으로 따라가기. 각 변수에 어떤 값이 들어가는지 표를 만든다.
  3. 15~20분 — 스스로 코드 작성. 막히면 전체 정답을 바로 보지 말고 핵심 개념이나 첫 번째 힌트만 본다.
  4. 10분 — 해설과 내 풀이 비교. 틀린 이유를 “인덱스 실수”, “패턴을 몰랐음”, “조건을 잘못 해석함” 중 하나로 기록한다.
  5. 5~10분 — 해설을 닫고 다시 작성. 복사해서 맞힌 건 내 실력이 아니야. 빈 화면에서 다시 쓸 수 있어야 해.
  6. 다음 날 — 같은 코드를 안 보고 재현. 그 다음 3일·7일·14일 뒤에 짧게 다시 푼다.

외워야 하는 것과 이해해야 하는 것

외워도 되는 것

  • 자주 쓰는 Java API 이름과 사용 형태
  • 투 포인터에서 포인터를 움직이는 기본 규칙
  • BFS의 큐·방문 처리 순서
  • 이분 탐색과 DP의 기본 코드 뼈대

이유까지 알아야 하는 것

  • 왜 그 조건에서 포인터를 움직이는가
  • 방문 체크를 언제 해야 중복 탐색을 막는가
  • dp[i]가 정확히 무엇을 뜻하는가
  • 정렬 순서가 왜 정답에 영향을 주는가

결론은 이해 1번 → 코드 뼈대 암기 → 안 보고 재현 → 다른 문제에 적용이야. “닥치고 외우기”만 하면 문제 모양이 살짝 바뀌었을 때 무너지지만, 이해만 하고 반복하지 않아도 시험장에서 코드가 안 나와. 둘 다 필요해.

이 가이드를 사용하는 순서

처음부터 모든 단원을 완벽하게 이해하려 하지 마. ① 기초·복잡도 → ② 문자열·배열 → ③ 해시·스택/큐 → ④ 정렬·탐색 → ⑤ 투 포인터 → ⑥ DFS/BFS → ⑦ 그리디 → ⑧ DP 순서로 공부하는 걸 추천해. 한 단원에서 추천 문제 1~2개를 풀어 보고, 설명 없이 기본 코드를 다시 쓸 수 있으면 다음으로 넘어가.

중요: 처음에는 어려운 Lv.3 문제를 붙들고 자존심 싸움 하지 말기. 지금은 실력 증명보다 “기본 패턴을 알아보고 재현할 수 있는 상태”를 만드는 게 우선이야.

문자열

문자 인덱스, 문자열 비교, 빈도 세기, StringBuilder를 예제로 익힌다.

문자열은 “글자들이 순서대로 붙어 있는 것”

"cat"은 문자 c, a, t가 차례대로 있는 문자열이야. 첫 번째 글자의 인덱스는 0이야. 그래서 str.charAt(0)은 c를 반환하고, str.length()는 3을 반환해.

Java의 String은 한 번 만들어지면 내부 내용을 직접 바꾸지 않아. 예를 들어 str = str + "!"은 기존 문자열에 글자를 붙여 바꾸는 것처럼 보여도, 새로운 문자열을 만들어 변수에 다시 넣는 방식이야. 여러 번 붙일 때는 StringBuilder가 편리하다.

기본 예제: 글자 하나씩 확인하기

Java 예제
String str = "cat";

for (int i = 0; i < str.length(); i++) {
    char c = str.charAt(i);
    System.out.println(c);
}

반복문 첫 회에는 i=0이라 c, 다음에는 i=1이라 a, 마지막에는 i=2라 t를 출력해. charAt(i)의 i는 “몇 번째 글자인지”를 뜻하는 번호야. 실제 사람의 첫 번째는 Java에서 인덱스 0이라는 점을 기억하자.

패턴 1 — 문자열 뒤집기와 팰린드롬

팰린드롬은 앞에서 읽어도 뒤에서 읽어도 같은 문자열이야. 예를 들어 "level"은 팰린드롬이고 "java"는 아니야. 가장 쉬운 방법은 문자열을 뒤집은 뒤 원본과 같은지 비교하는 거야.

Java 예제
String str = "level";
String reversed = new StringBuilder(str).reverse().toString();
boolean isPalindrome = str.equals(reversed);

reverse()는 뒤집고, toString()은 결과를 String으로 돌려줘. 문자열의 내용 비교는 ==가 아니라 equals()를 써. ==는 문자열 내용이 아니라 참조가 같은지 비교하는 용도라서 코테 문자열 비교에는 보통 맞지 않아.

패턴 2 — 글자 빈도 세기

문자열에서 알파벳이 몇 번 나오는지 세고 싶다고 해 보자. 알파벳 소문자는 26개뿐이니 숫자 26개를 저장하는 칸을 만들고, 각 글자가 나올 때마다 해당 칸을 1씩 올리면 돼.

Java 예제
String str = "banana";
int[] freq = new int[26];

for (char c : str.toCharArray()) {
    freq[c - 'a']++;
}
// b는 freq[1], a는 freq[0], n은 freq[13]에 저장된다.

c - 'a'는 알파벳을 0~25 숫자로 바꾸는 트릭이야. 단, 이 코드는 영문 소문자 a~z만 입력된다는 조건이 있어야 해. 대문자나 한글이 들어오면 배열 범위를 벗어날 수 있어. 모든 문자에 대응해야 한다면 HashMap<Character, Integer>를 쓰면 돼.

패턴 3 — 숫자만 남기기와 문자열 조립

replaceAll()은 정규식에 맞는 부분을 바꿔 줘. "[^0-9]"는 숫자 0~9가 아닌 문자 하나를 뜻하므로, 아래 코드는 숫자가 아닌 문자를 모두 지워.

Java 예제
String raw = "전화: 010-1234-5678";
String digits = raw.replaceAll("[^0-9]", "");
// digits: "01012345678"

StringBuilder sb = new StringBuilder();
for (int i = 1; i <= 5; i++) {
    sb.append(i);
}
String result = sb.toString(); // "12345"

StringBuilder의 append()는 뒤에 내용을 이어 붙여. 문자열을 반복해서 조립할 때 유용해. 다만 Integer.parseInt(digits)는 숫자 문자열이 비어 있거나 int 범위를 넘으면 예외가 발생할 수 있으니, 입력 조건을 확인해야 해.

문자열 문제를 만나면 이 순서로 생각하기

  1. 문자열을 글자 단위로 볼까, 부분 문자열 단위로 볼까?
  2. 원본을 바꿔야 할까? 단순 검색이면 String 메서드로 충분하고, 반복 조립이면 StringBuilder를 고려한다.
  3. 글자의 위치가 중요할까? 그렇다면 인덱스·투 포인터를 생각한다.
  4. 글자별 등장 횟수가 중요할까? 그렇다면 빈도 배열 또는 HashMap을 생각한다.
  5. 숫자나 특정 문자만 뽑아야 할까? replaceAll 정규식 또는 직접 순회를 생각한다.

이 단원에서 먼저 외울 것

  • str.length(): 문자열 길이
  • str.charAt(i): i번째 문자
  • str.toCharArray(): 문자 배열로 변환
  • str.equals(other): 내용 비교
  • new StringBuilder(str).reverse().toString(): 뒤집기
  • sb.append(value): 문자열 조립
직접 생각해 보기: 문자열 내용이 같은지 확인하려면 보통 ==와 equals() 중 무엇을 사용할까?
답

equals()를 사용한다.

왜?

String의 ==는 두 변수가 같은 객체를 가리키는지 확인하고, equals()는 문자열 내용이 같은지 확인한다.

배열과 2차원 배열

배열 인덱스, 정렬, 누적합, 소수 판별, 격자 이동을 하나씩 따라간다.

배열은 “번호가 붙은 사물함”

배열은 같은 종류의 값을 여러 개 저장해 두는 공간이야. int[] arr = {4, 7, 2}라고 하면 번호 0번 칸에 4, 1번 칸에 7, 2번 칸에 2가 들어 있어. 배열 길이는 3이고 마지막 인덱스는 2야. 그래서 마지막 원소는 arr[arr.length - 1]로 접근해.

배열 문제의 기본은 “몇 번째 칸을 보고 있는지”를 정확히 추적하는 거야. 범위를 넘어 arr[3]처럼 접근하면 ArrayIndexOutOfBoundsException이 발생해.

패턴 1 — 최댓값·최솟값·합

Java 예제
int[] arr = {4, 7, 2, 9};
int sum = 0;
int max = arr[0];
int min = arr[0];

for (int value : arr) {
    sum += value;
    max = Math.max(max, value);
    min = Math.min(min, value);
}
// sum = 22, max = 9, min = 2

처음 max를 0으로 잡으면 배열의 값이 전부 음수일 때 잘못된 답이 될 수 있어. 그래서 비어 있지 않은 배열이라는 조건에서 첫 원소 arr[0]로 시작하는 게 안전해. for (int value : arr)는 배열 원소를 하나씩 꺼내 쓰는 반복문이야.

패턴 2 — 정렬

정렬은 데이터를 순서대로 배열하는 일이야. Arrays.sort(arr)는 int 배열을 오름차순으로 정렬해. 숫자 3, 1, 2는 1, 2, 3이 된다. 정렬을 먼저 하면 최소값·최대값을 쉽게 찾거나, 이분 탐색과 그리디를 사용할 수 있는 경우가 많아.

Java 예제
int[] nums = {5, 1, 8, 2};
Arrays.sort(nums); // [1, 2, 5, 8]

Integer[] boxed = {5, 1, 8, 2};
Arrays.sort(boxed, Collections.reverseOrder()); // [8, 5, 2, 1]

기본형 int[]에는 Collections.reverseOrder()를 직접 적용할 수 없어. 내림차순 정렬 예시는 Integer[]처럼 객체 배열을 사용해. 숫자가 매우 크다면 비교식 a - b보다 Integer.compare(a, b)를 사용하는 것이 오버플로 위험을 피하는 데 좋다.

패턴 3 — 누적합: 앞에서 계산한 합을 재사용하기

배열에서 2번~5번 칸의 합처럼 구간 합을 자주 물어보는 문제가 있어. 매번 해당 구간을 다시 더하면 질문이 많을 때 느려질 수 있어. 누적합은 “첫 번째부터 지금 칸까지의 합”을 미리 저장하는 배열이야.

예를 들어 arr = [2, 4, 1, 3]이면 누적합은 prefix = [2, 6, 7, 10]이야. 인덱스 1부터 3까지의 합은 prefix[3] - prefix[0] = 10 - 2 = 8이 돼. 아래 코드는 0부터 시작하는 인덱스 기준이야.

Java 예제
int[] arr = {2, 4, 1, 3};
int[] prefix = new int[arr.length];
prefix[0] = arr[0];

for (int i = 1; i < arr.length; i++) {
    prefix[i] = prefix[i - 1] + arr[i];
}

// 인덱스 left부터 right까지의 합
int rangeSum = prefix[right];
if (left > 0) {
    rangeSum -= prefix[left - 1];
}

왜 빼는지 이해하려면 전체 앞부분을 생각해 봐. prefix[right]는 0부터 right까지 전부 포함해. 우리가 원하는 건 left부터니까, 필요 없는 0~left-1의 합을 빼는 거야. 단, 인덱스와 숫자 위치를 혼동하지 말고 문제의 범위가 0-based인지 1-based인지 확인해야 해.

패턴 4 — 소수 목록을 빠르게 만들기: 에라토스테네스의 체

소수는 1보다 큰 수 중에서 1과 자기 자신으로만 나누어 떨어지는 수야. 소수를 하나씩 매번 나눠 보는 대신, 소수의 배수는 소수가 아니라고 표시하면 빠르게 목록을 만들 수 있어. 2의 배수, 3의 배수, 5의 배수처럼 지워 나가는 방식이지.

Java 예제
int n = 30;
boolean[] isPrime = new boolean[n + 1];
Arrays.fill(isPrime, true);
isPrime[0] = false;
isPrime[1] = false;

for (int i = 2; i * i <= n; i++) {
    if (!isPrime[i]) continue;
    for (int j = i * i; j <= n; j += i) {
        isPrime[j] = false;
    }
}

isPrime[x]가 true면 현재까지 소수 후보라는 뜻이야. j = i * i부터 시작하는 이유는 i보다 작은 배수들은 더 작은 소수의 단계에서 이미 지워졌기 때문이야. 이 코드는 n이 1 이상인 상황을 가정해. 실전에서는 입력 범위와 배열 크기를 먼저 확인하자.

2차원 배열과 dx/dy

2차원 배열은 표나 게임판처럼 행과 열이 있는 배열이야. grid[x][y]에서 x는 행 번호, y는 열 번호로 쓰는 경우가 많아. 위·아래·왼쪽·오른쪽으로 움직일 때는 이동량을 배열에 저장해 두면 반복 코드가 줄어들어.

Java 예제
int[] dx = {-1, 1, 0, 0}; // 행 이동: 위, 아래, 그대로, 그대로
int[] dy = {0, 0, -1, 1}; // 열 이동: 그대로, 그대로, 왼쪽, 오른쪽

for (int d = 0; d < 4; d++) {
    int nx = x + dx[d];
    int ny = y + dy[d];

    if (nx < 0 || nx >= rows || ny < 0 || ny >= cols) {
        continue; // 격자 밖이면 건너뛴다
    }
    // 여기부터는 grid[nx][ny]에 접근해도 범위 안이다.
}

rows는 행의 개수, cols는 열의 개수야. x와 y를 반대로 쓰면 방향이 뒤틀릴 수 있으니, 문제마다 “첫 번째 인덱스는 행, 두 번째는 열”인지 확인하고 일관되게 사용하자.

배열 문제 체크리스트

  • 인덱스는 0부터 시작한다. 길이가 n인 배열의 유효 인덱스는 0~n-1이다.
  • 정렬이 필요한 이유가 무엇인지 말할 수 있는가?
  • 같은 구간의 합을 여러 번 구한다면 누적합이 유리한가?
  • 2차원 이동은 범위 체크를 한 후 배열에 접근하는가?
  • 입력이 비어 있을 가능성이나 n이 작은 경우도 고려했는가?
직접 생각해 보기: arr가 [2, 4, 1, 3]이고 prefix가 [2, 6, 7, 10]일 때 인덱스 1~3의 합은?
답

8이다.

왜?

prefix[3]은 0~3의 합인 10이고, prefix[0]은 원하지 않는 0번째 값 2다. 따라서 10 - 2 = 8이다.

투 포인터와 슬라이딩 윈도우

구간을 처음부터 다시 계산하지 말고, 왼쪽·오른쪽 경계를 움직이며 관리한다.

투 포인터와 슬라이딩 윈도우가 필요한 이유

연속된 숫자의 합을 찾는다고 해 보자. 단순한 방법은 시작점을 하나 정하고, 그 뒤에 가능한 구간을 전부 더하는 거야. 하지만 구간을 조금 옮길 때 이전에 더한 숫자를 또 더한다면 낭비가 생기지.

투 포인터는 보통 두 위치(lt, rt)를 움직이며 범위를 관리하는 방법이고, 슬라이딩 윈도우는 그중에서도 창문처럼 연속 구간을 옆으로 밀어 가며 유지하는 기법이야. 둘은 겹치는 개념이지만 완전히 같은 말은 아니야.

투 포인터의 핵심: 범위가 어떻게 변하는지 보기

예를 들어 양수 배열 [1, 2, 1, 3, 1]에서 합이 3인 연속 구간을 찾아 보자. 처음에는 왼쪽 lt=0, 오른쪽 rt=0이고 합은 1이야. 합이 3보다 작으므로 오른쪽을 늘려 숫자 2를 더해. 합이 3이 되었으니 구간을 하나 찾았고, 다음 숫자를 더하면 합이 커지니 왼쪽을 줄여 범위를 조절할 수 있어.

right유효 구간합 / 결과
0[1]1 — 작으니 확장
1[1,2]3 — 구간 1개 발견
2[2,1]3 — 왼쪽 1을 빼고 구간 2개째
3[3]3 — 구간 3개째 발견
4[1]1 — target보다 작음

이 예제는 모든 배열 원소가 양수야. 양수만 있으면 오른쪽 숫자를 더할수록 합이 커지고 왼쪽 숫자를 빼면 합이 작아져. 그래서 어떤 방향으로 움직여야 할지 판단할 수 있어.

템플릿 — 양수 배열에서 합이 target인 연속 구간 개수 세기

Java 예제
int left = 0;
int sum = 0;
int count = 0;

for (int right = 0; right < arr.length; right++) {
    sum += arr[right]; // 오른쪽 끝을 한 칸 확장

    while (sum > target && left <= right) {
        sum -= arr[left]; // 합이 너무 크면 왼쪽을 줄임
        left++;
    }

    if (sum == target) {
        count++;
    }
}

전제: 이 기본 템플릿은 배열 원소가 양수이고, 찾는 값이 양수인 상황을 설명하는 패턴이야. 음수 원소가 있으면 오른쪽 숫자를 추가했을 때 합이 작아질 수도 있으므로 이 논리가 깨져. 또 이 코드는 각 오른쪽 끝에서 합이 target인 구간을 최대 하나 찾는 형태로, 양수 배열에서는 적합하지만 0이 포함되거나 모든 가능한 구간을 세야 하는 다른 조건에서는 별도 검토가 필요해.

코드 읽는 법: right는 오른쪽 끝을 계속 이동해. sum이 너무 크면 left를 옮겨 왼쪽 값을 빼. 마지막에 합이 target과 같은지 검사해. 구간을 일일이 다시 계산하는 대신 더하고 빼는 값만 갱신하는 것이 핵심이야.

고정 크기 슬라이딩 윈도우

이번에는 길이가 항상 3인 연속 구간 중 합이 가장 큰 것을 찾는다고 하자. 처음 세 숫자의 합을 계산한 뒤 구간을 오른쪽으로 한 칸 옮길 때, 이전 구간의 맨 왼쪽 숫자 하나를 빼고 새로 들어온 오른쪽 숫자 하나를 더하면 돼.

Java 예제
int k = 3;
int windowSum = 0;
for (int i = 0; i < k; i++) {
    windowSum += arr[i];
}
int maxSum = windowSum;

for (int right = k; right < arr.length; right++) {
    windowSum += arr[right];       // 새로 들어온 값
    windowSum -= arr[right - k];   // 창문에서 빠진 값
    maxSum = Math.max(maxSum, windowSum);
}

처음부터 매번 세 숫자를 다시 더하면 같은 덧셈을 반복해. 이 방식은 창문이 움직일 때 값 2개만 반영하므로 각 원소를 대체로 한 번씩 처리해 O(n)에 해결할 수 있어. 단, 배열 길이가 k보다 작은 경우에는 초기 구간을 만들 수 없으니 입력 조건을 확인해야 해.

  • 문제가 연속된 구간이나 정렬된 배열의 두 위치를 다루는가?
  • 포인터를 한 방향으로만 움직여도 답을 놓치지 않는 이유가 있는가?
  • 합 조건에서 원소가 양수인가? 음수가 섞이면 단조성이 깨질 수 있다.
  • 고정 길이 구간인가, 조건에 따라 길이가 바뀌는 구간인가?
  • 구간이 이동할 때 빠지는 값과 새로 들어오는 값을 정확히 구분했는가?

왜?

HashMap과 TreeSet

빈도 세기, 존재 여부, 정렬된 집합을 문제 조건과 연결한다.

HashMap은 “이름표가 붙은 보관함”

배열은 0, 1, 2처럼 번호로 값을 찾지만, HashMap은 키(key)로 값(value)을 찾는 자료구조야. 예를 들어 이름을 키로 하고 점수를 값으로 저장할 수 있어. "철수" → 90 같은 관계를 기억하기 쉽지.

코테에서는 “각 숫자가 몇 번 나왔지?”, “이 이름이 이미 있었지?”, “이 단어의 개수는?” 같은 문제에 자주 사용해. 평균적으로 삽입·조회가 빠르지만, 순서를 자동으로 정렬해 주지는 않아.

패턴 1 — getOrDefault로 등장 횟수 세기

Java 예제
String[] names = {"kim", "lee", "kim", "park", "kim"};
Map<String, Integer> count = new HashMap<>();

for (String name : names) {
    count.put(name, count.getOrDefault(name, 0) + 1);
}
// kim=3, lee=1, park=1

getOrDefault(name, 0)는 name이 이미 있으면 저장된 숫자를 가져오고, 없으면 0을 가져와. 거기에 1을 더해서 다시 저장해. 첫 등장한 kim은 0+1=1, 두 번째 kim은 1+1=2가 되는 식이야.

패턴 2 — 두 배열 또는 두 그룹 비교

“참가자 목록에는 있는데 완주자 목록에는 없는 사람”처럼 두 목록의 차이를 찾는다고 해 보자. 참가자를 한 명씩 지울 수 있도록 빈도를 세어 두면, 중복 이름이 있어도 처리할 수 있어.

Java 예제
Map<String, Integer> count = new HashMap<>();
for (String name : participants) {
    count.put(name, count.getOrDefault(name, 0) + 1);
}

for (String name : finishers) {
    count.put(name, count.get(name) - 1);
}

for (Map.Entry<String, Integer> entry : count.entrySet()) {
    if (entry.getValue() > 0) {
        System.out.println(entry.getKey());
    }
}

완주한 이름이 나올 때마다 개수를 하나 줄여. 마지막에 0보다 큰 수가 남으면 참가자 목록에 더 많이 있었다는 뜻이야. 이 방식은 같은 이름이 여러 번 나오는 경우에도 “몇 명”인지 계산한다. 다만 입력에 없는 키를 get(name)으로 바로 가져오면 null이 될 수 있으므로, 이 예제는 모든 finisher가 participants에 있다고 가정해.

TreeSet과 TreeMap: 자동으로 정렬해 주는 도구

HashSet은 중복을 제거하지만 정렬 순서를 약속하지 않아. TreeSet은 중복을 제거하면서 정렬된 순서를 유지해. “현재 숫자보다 작거나 같은 값 중 가장 큰 수”처럼 가까운 값을 찾아야 할 때 유용해.

Java 예제
TreeSet<Integer> set = new TreeSet<>();
set.add(10);
set.add(3);
set.add(7);
set.add(7); // 중복은 한 번만 저장

System.out.println(set);          // [3, 7, 10]
System.out.println(set.floor(8));  // 7: 8 이하에서 가장 큰 값
System.out.println(set.ceiling(8));// 10: 8 이상에서 가장 작은 값

floor(x)는 x 이하에서 가장 큰 값, ceiling(x)는 x 이상에서 가장 작은 값을 의미해. 조건을 만족하는 값이 없으면 null을 반환할 수 있다는 것도 기억하자. 정렬을 유지하는 비용 때문에 보통 HashSet보다 삽입·조회가 느리지만, “정렬된 상태”가 필요할 때 사용해.

어떤 자료구조를 고르면 될까?

배열위치 번호로 빠르게 접근i번째 원소, 고정된 범위
HashMap키에 대응하는 값 저장빈도수, 존재 횟수, 매핑
HashSet중복 없이 존재 여부 관리이미 봤는지 확인
TreeSet중복 제거 + 정렬 유지이하 최댓값·이상 최솟값
TreeMap키 기준 정렬된 key-value정렬된 범위별 집계

이 단원에서 외울 코드 뼈대

Java 예제
// 빈도수 증가
map.put(key, map.getOrDefault(key, 0) + 1);

// 키가 있는지 확인
if (map.containsKey(key)) {
    // 이미 존재한다
}

// 모든 키와 값을 순회
for (Map.Entry<String, Integer> entry : map.entrySet()) {
    String key = entry.getKey();
    int value = entry.getValue();
}

왜?

Set은 존재 여부와 중복 제거에는 좋지만 각 이름이 몇 번 나왔는지를 그대로 저장하지 않는다. HashMap은 키와 숫자를 연결할 수 있다.

스택과 큐

스택·큐·우선순위 큐의 차이를 일상적인 예와 Java API로 익힌다.

스택과 큐는 줄 서는 방식이 다르다

스택(Stack)은 접시를 쌓는 것과 같아. 마지막에 올린 접시를 가장 먼저 꺼내. 이것을 LIFO(Last In, First Out)라고 해. 괄호 짝 맞추기, 되돌아가기, 최근 상태부터 처리하기 등에 쓴다.

큐(Queue)는 줄 서기와 같아. 먼저 들어온 사람을 먼저 처리해. 이것을 FIFO(First In, First Out)라고 해. BFS처럼 가까운 순서대로 탐색할 때 사용해.

Java에서는 예전 Stack 클래스 대신, 스택과 큐 모두에 활용할 수 있는 ArrayDeque를 기본 선택지로 기억해 두면 좋아.

스택 기본 API

Java 예제
Deque<Integer> stack = new ArrayDeque<>();
stack.push(10);   // 맨 위에 넣기
stack.push(20);
int top = stack.peek(); // 20을 확인하지만 제거하지 않음
int value = stack.pop(); // 20을 꺼내고 제거
boolean empty = stack.isEmpty();

push는 넣기, peek은 확인만 하기, pop은 꺼내면서 제거하기야. 비어 있는 스택에서 pop()하면 예외가 발생하므로 isEmpty()를 확인하는 습관을 들이자.

대표 문제 — 괄호가 올바른지 확인하기

문자열 "(())"는 괄호가 올바르고, "())("는 올바르지 않아. 여는 괄호를 만날 때마다 저장하고, 닫는 괄호가 나오면 직전에 열린 괄호를 하나 없애면 돼. 닫을 것이 없는데 닫는 괄호가 나오면 그 즉시 실패야.

Java 예제
boolean isValid(String s) {
    Deque<Character> stack = new ArrayDeque<>();

    for (char c : s.toCharArray()) {
        if (c == '(') {
            stack.push(c);
        } else { // 입력이 '('와 ')'만으로 이루어졌다고 가정
            if (stack.isEmpty()) {
                return false; // 짝지을 여는 괄호가 없음
            }
            stack.pop();
        }
    }
    return stack.isEmpty(); // 여는 괄호가 남지 않아야 성공
}

끝에서 스택이 비어 있지 않다면 여는 괄호가 남아 있다는 뜻이야. 이 코드는 입력에 소괄호 두 종류만 있다고 가정해. 여러 종류의 괄호가 섞인 문제에서는 여는 괄호의 종류도 저장해서 짝이 맞는지 비교해야 해.

큐 기본 API와 BFS 준비

Java 예제
Queue<Integer> queue = new ArrayDeque<>();
queue.offer(10); // 뒤에 넣기
queue.offer(20);
int first = queue.peek(); // 맨 앞 확인: 10
int removed = queue.poll(); // 맨 앞에서 꺼내기: 10
boolean empty = queue.isEmpty();

offer는 큐에 넣기, poll은 맨 앞에서 꺼내기, peek은 맨 앞 확인이야. 비어 있는 큐에서 poll()과 peek()은 null을 반환할 수 있어. 숫자 0과 “값이 없음”을 구분해야 하는 문제에서는 반환값 처리에 신경 써.

우선순위 큐는 “먼저 온 순서”가 아니다

PriorityQueue는 넣은 순서대로 꺼내는 자료구조가 아니야. 기본 설정에서는 가장 작은 값이 먼저 나와. 매번 가장 작은 비용, 가장 낮은 점수, 가장 가까운 후보를 골라야 할 때 사용해.

Java 예제
PriorityQueue<Integer> minHeap = new PriorityQueue<>();
minHeap.offer(7);
minHeap.offer(2);
minHeap.offer(5);
System.out.println(minHeap.poll()); // 2

PriorityQueue<Integer> maxHeap =
        new PriorityQueue<>(Comparator.reverseOrder());
maxHeap.offer(7);
maxHeap.offer(2);
maxHeap.offer(5);
System.out.println(maxHeap.poll()); // 7

우선순위 큐는 스택이나 일반 큐와 목적이 달라. 최솟값/최댓값을 반복해서 꺼내야 할 때 사용하고, 모든 원소가 항상 정렬된 리스트처럼 보장되는 것은 아니야.

문제에서 어떤 구조인지 알아보는 단서

  • “가장 최근의”, “되돌리기”, “괄호 짝” → 스택을 의심한다.
  • “먼저 들어온 순서”, “레벨 순서”, “최단 거리” → 큐를 의심한다.
  • “매번 가장 작은/큰 값부터 선택” → 우선순위 큐를 의심한다.
  • 비어 있는 자료구조에서 꺼내는 경우가 생길 수 있는지 검사한다.

정렬과 이분 탐색

정렬 기준을 만드는 법과 범위를 절반씩 줄이는 논리를 익힌다.

정렬은 순서를 만드는 것, 이분 탐색은 절반씩 버리는 것

정렬은 데이터를 작은 순서나 큰 순서로 배열하는 거야. 정렬하면 “가장 작은 값”, “서로 가까운 값”, “특정 조건의 앞뒤 순서”를 다루기 쉬워져.

이분 탐색은 이미 정렬된 데이터에서 가운데 값을 보고, 찾는 값이 가운데보다 작은지 큰지에 따라 절반을 버리는 방법이야. 정렬되지 않은 배열에서는 가운데를 보고 어느 쪽에 답이 있는지 알 수 없기 때문에 사용할 수 없어.

Comparator: 정렬 기준을 직접 말해 주기

객체나 2차원 배열은 어떤 기준으로 정렬할지 지정해야 할 때가 있어. 회의가 끝나는 시간이 빠른 순서로 정렬하고, 끝나는 시간이 같으면 시작 시간이 빠른 순서로 정렬한다고 해 보자.

Java 예제
int[][] meetings = {
    {3, 5}, {1, 4}, {4, 4}, {2, 3}
};

Arrays.sort(meetings, (a, b) -> {
    int byEnd = Integer.compare(a[1], b[1]);
    if (byEnd != 0) return byEnd;
    return Integer.compare(a[0], b[0]);
});

a[0]은 시작 시간, a[1]은 끝나는 시간이라고 약속한 거야. 먼저 끝나는 시간을 비교하고, 둘이 같으면 시작 시간을 비교해. 비교식 a[1] - b[1]은 값이 아주 크면 오버플로 위험이 있을 수 있으므로 Integer.compare가 안전한 습관이야.

이분 탐색 — 값을 찾는 기본형

정렬된 배열 [2, 5, 8, 12, 16, 23, 38]에서 16을 찾는다고 하자. 가운데를 확인하고, 목표 16이 가운데 값보다 크면 왼쪽 절반을 버려. 남은 절반에서 다시 가운데를 확인해. 매번 살펴볼 범위가 대략 절반이 되므로 빠르다.

Java 예제
int binarySearch(int[] arr, int target) {
    int left = 0;
    int right = arr.length - 1;

    while (left <= right) {
        int mid = left + (right - left) / 2;

        if (arr[mid] == target) {
            return mid;
        } else if (arr[mid] < target) {
            left = mid + 1;  // target은 오른쪽에 있을 수 있음
        } else {
            right = mid - 1; // target은 왼쪽에 있을 수 있음
        }
    }
    return -1; // 찾지 못함
}

left와 right는 아직 확인할 수 있는 범위의 양 끝이야. left > right가 되면 더 확인할 칸이 없다는 뜻이야. 중간 인덱스는 left + (right-left)/2로 계산하면 (left+right)/2보다 정수 오버플로 위험을 줄일 수 있어.

파라메트릭 서치 — “가능한가?”를 이분 탐색하기

이름은 어려워 보이지만 질문은 단순해. “최소 몇 분이면 모든 사람을 처리할 수 있을까?”, “길이를 얼마까지 늘려도 조건을 만족할까?”처럼 어떤 숫자를 정했을 때 가능/불가능을 판단할 수 있는 문제야. 숫자가 커질수록 무조건 가능해지거나, 숫자가 커질수록 무조건 불가능해지는 단조성이 있으면 이분 탐색을 적용할 수 있어.

예를 들어 “조건을 만족하는 최소 값”을 구하고, can(x)가 x에서 가능한지 알려준다고 하자. x가 커질수록 조건을 만족하기 쉬운 형태라면, 가능할 때 더 작은 값도 가능한지 왼쪽을 살펴봐.

Java 예제
// 조건을 만족하는 최소 정수 찾기
int left = minValue;
int right = maxValue;
int answer = -1; // 가능한 값이 없으면 -1 유지

while (left <= right) {
    int mid = left + (right - left) / 2;

    if (can(mid)) {
        answer = mid;       // 일단 정답 후보
        right = mid - 1;    // 더 작은 값도 가능한지 확인
    } else {
        left = mid + 1;     // 너무 작아서 불가능 → 키운다
    }
}

핵심은 can(mid)가 어떤 뜻인지, 값이 커질 때 true/false가 어떤 방향으로 바뀌는지 먼저 설명할 수 있어야 한다는 점이야. “최소 가능한 값”과 “최대 가능한 값”은 포인터 이동 방향이 반대일 수 있으므로, 이 코드의 좌우 이동을 무조건 암기해서 모든 문제에 붙이면 안 돼.

  • 정렬 기준이 여러 개라면 우선순위 순서대로 비교하는가?
  • 가능 여부 함수가 숫자에 따라 한 방향으로만 바뀌는가?
  • 정답을 찾았을 때 끝낼지, 더 작은/큰 후보가 있는지 확인할지 결정했는가?
  • 배열이 비어 있거나 답이 없는 상황의 반환값을 정했는가?

재귀와 DFS

그래프를 연결 목록으로 표현하고, 방문한 점을 표시하며 깊게 탐색한다.

그래프는 “점과 선으로 연결된 관계”

지도 속 장소와 길, 사람과 친구 관계, 웹페이지와 링크를 점과 선으로 표현할 수 있어. 점을 정점(vertex), 연결선을 간선(edge)이라고 불러. “A와 B가 연결되어 있나?”, “연결된 곳은 모두 몇 개나 있나?” 같은 문제를 그래프로 표현할 수 있어.

그래프를 코드로 표현하는 쉬운 방법은 각 점마다 “나와 연결된 점 목록”을 저장하는 인접 리스트야. 정점이 적고 간선이 일부만 있는 문제에서는 보통 인접 행렬보다 메모리를 덜 사용한다.

인접 리스트를 만드는 방법

Java 예제
int n = 5;
List<List<Integer>> graph = new ArrayList<>();
for (int i = 0; i < n; i++) {
    graph.add(new ArrayList<>());
}

// 0과 1이 연결된 무방향 그래프
graph.get(0).add(1);
graph.get(1).add(0);

// 0번 정점과 연결된 정점 확인
for (int next : graph.get(0)) {
    System.out.println(next);
}

무방향 그래프는 A와 B가 연결되면 A의 목록에도 B를, B의 목록에도 A를 추가해. 단방향 그래프라면 문제에서 주어진 방향대로만 저장해야 해. 정점 번호가 1부터 n까지 주어지는지 0부터 n-1까지 주어지는지도 주의하자.

DFS는 한 갈래를 깊게 들어갔다가 돌아오는 탐색

미로에서 길을 따라 계속 가다가 막히면 직전 갈림길로 돌아오는 걸 떠올리면 돼. 이것이 DFS(깊이 우선 탐색)의 느낌이야. 재귀 함수로 작성할 수 있고, 방문한 점을 기록하는 visited가 필수야. 방문 체크를 하지 않으면 A→B→A→B처럼 같은 곳을 계속 돌 수 있어.

Java 예제
void dfs(int current, List<List<Integer>> graph, boolean[] visited) {
    visited[current] = true; // 이 정점은 방문했음

    for (int next : graph.get(current)) {
        if (!visited[next]) {
            dfs(next, graph, visited);
        }
    }
}

함수를 호출할 때마다 현재 정점을 방문 처리하고, 연결된 정점 중 아직 안 간 곳으로 다시 들어가. 더 들어갈 곳이 없으면 함수가 끝나면서 이전 위치로 돌아와. 이처럼 함수가 자신을 부르는 방식을 재귀라고 해.

재귀는 편하지만 연결이 아주 깊은 그래프에서는 호출 스택이 넘쳐 StackOverflowError가 날 수 있어. 입력 범위가 크면 반복문과 명시적인 스택을 쓰는 방법도 고려해.

연결 요소 개수 세기

지도에서 서로 연결되어 있는 덩어리가 몇 개인지 세는 문제를 생각해 보자. 전체 정점을 0부터 확인하면서 아직 방문하지 않은 정점을 만나면 새로운 덩어리의 시작이야. 그 정점에서 DFS를 실행해 연결된 곳을 모두 방문하고, 덩어리 수를 1 늘려.

Java 예제
int components = 0;
boolean[] visited = new boolean[n];

for (int i = 0; i < n; i++) {
    if (!visited[i]) {
        components++;
        dfs(i, graph, visited);
    }
}

이 코드는 모든 정점을 최소 한 번 확인해. 이미 방문한 정점은 같은 연결 덩어리에 포함되므로 새 DFS를 시작하지 않아. 첫 정점을 0으로 쓸지 1로 쓸지에 맞춰 배열의 크기와 반복 범위를 맞춰야 한다.

재귀를 읽을 때 종이에 쓸 세 가지

  • 종료 조건: 언제 함수가 더 이상 자신을 호출하지 않는가?
  • 현재 상태: 지금 함수가 처리하는 정점 또는 선택은 무엇인가?
  • 다음 호출: 어떤 조건일 때 다음 정점으로 들어가는가?
직접 생각해 보기: DFS에서 visited 처리를 하지 않으면 연결된 두 정점 사이를 계속 오갈 수 있을까?
답

왜?

무방향 그래프는 A에서 B로 갈 수 있으면 B에서도 A로 갈 수 있다. 방문 처리가 없다면 재귀가 반복될 수 있다.

BFS와 최단거리

큐를 활용해 가까운 상태부터 방문하고, 거리 정보를 갱신한다.

BFS는 “가까운 곳부터 층층이” 탐색하기

출발점에서 한 번에 갈 수 있는 곳을 먼저 보고, 그 다음 두 번 이동해야 갈 수 있는 곳을 보는 방식이 BFS(너비 우선 탐색)야. 사람이 여러 갈림길로 퍼지는 그림을 떠올리면 돼. 이동 비용이 모두 1인 그래프라면 BFS가 도착점까지의 최단 이동 횟수를 구할 수 있어.

DFS는 한 갈래를 깊게 들어가고, BFS는 가까운 곳부터 넓게 퍼져. 그래서 목적에 따라 선택해. 최단거리 문제라고 무조건 BFS인 것은 아니고, 간선마다 이동 비용이 다르면 다익스트라 같은 다른 알고리즘이 필요할 수 있어.

BFS 기본 템플릿

Java 예제
int[] distance = new int[n];
Arrays.fill(distance, -1); // -1은 아직 방문하지 않았다는 표시
Queue<Integer> queue = new ArrayDeque<>();

int start = 0;
distance[start] = 0;
queue.offer(start);

while (!queue.isEmpty()) {
    int current = queue.poll();

    for (int next : graph.get(current)) {
        if (distance[next] != -1) continue; // 이미 방문함

        distance[next] = distance[current] + 1;
        queue.offer(next);
    }
}

큐에 넣을 때 방문 처리를 해. 여기서는 distance를 -1에서 0 이상으로 바꾸는 것이 방문 표시 역할을 해. 새 정점의 거리는 현재 정점의 거리 + 1이야. 모든 간선의 비용이 1이므로, 큐에서 먼저 발견한 경로가 가장 적은 이동 횟수를 갖는다.

distance를 0으로 초기화하고 별도 visited 없이 쓰면 출발점의 거리 0과 미방문 상태가 구분되지 않아. 그래서 -1 같은 “방문하지 않음” 값을 쓰거나 별도 visited 배열을 쓴다.

2차원 격자에서 BFS

미로에서 시작 칸부터 도착 칸까지 최소 몇 번 움직여야 하는지 구할 때 쓴다. 큐에는 현재 칸의 행·열을 넣고, 상하좌우로 움직인다. 새 칸이 격자 밖이거나 벽이거나 이미 방문한 곳이면 건너뛴다.

Java 예제
int rows = board.length;
int cols = board[0].length;
int[][] dist = new int[rows][cols];
for (int[] row : dist) Arrays.fill(row, -1);

int[] dx = {-1, 1, 0, 0};
int[] dy = {0, 0, -1, 1};
Queue<int[]> q = new ArrayDeque<>();
q.offer(new int[]{startX, startY});
dist[startX][startY] = 0;

while (!q.isEmpty()) {
    int[] cur = q.poll();
    int x = cur[0], y = cur[1];

    for (int d = 0; d < 4; d++) {
        int nx = x + dx[d];
        int ny = y + dy[d];
        if (nx < 0 || nx >= rows || ny < 0 || ny >= cols) continue;
        if (board[nx][ny] == 0) continue; // 예: 0은 벽이라고 가정
        if (dist[nx][ny] != -1) continue;

        dist[nx][ny] = dist[x][y] + 1;
        q.offer(new int[]{nx, ny});
    }
}

이 예제는 board에서 0이 벽이고 1이 이동 가능한 칸이라고 가정했어. 실제 문제의 벽/길 표현에 맞게 조건을 바꿔야 해. dist에는 시작점이 0, 한 번 움직인 칸은 1, 두 번 움직인 칸은 2가 저장된다. 문제에서 시작 칸도 이동 횟수에 포함하는 식으로 정의하면 결과에 1을 더하는 등 답의 정의에 맞게 조정해야 해.

방문 처리를 큐에서 꺼낼 때 하면 안 될까?

보통은 큐에 넣는 순간 방문 처리를 해야 해. 만약 큐에서 꺼낼 때까지 방문 표시를 하지 않으면, 같은 정점으로 가는 서로 다른 경로가 여러 개 있을 때 그 정점이 큐에 여러 번 들어갈 수 있어. 그러면 불필요한 작업이 늘고 거리 갱신도 헷갈리기 쉬워져.

외울 문장: “발견했을 때 거리 기록, 큐에 넣기. 큐에서 꺼낼 때는 이미 기록된 상태.”

BFS 문제 풀이 순서

  1. 정점이나 칸을 어떻게 표현할지 정한다: 숫자 하나, (행, 열), 혹은 상태 묶음.
  2. 방문 여부와 거리 정보를 저장할 배열을 준비한다.
  3. 시작점을 방문 처리하고 큐에 넣는다.
  4. 큐가 빌 때까지 하나 꺼내고, 이동 가능한 다음 위치를 확인한다.
  5. 범위 밖·벽·이미 방문한 위치는 건너뛴다.
  6. 새 위치에 거리와 방문을 기록한 뒤 큐에 넣는다.

답

왜?

BFS는 가까운 거리의 정점을 먼저 방문하므로 모든 간선 비용이 1인 그래프에서 최초로 도달한 거리가 최단 이동 횟수다.

그리디 알고리즘

매 순간의 선택이 전체 답으로 이어지는 이유를 문제 조건에서 확인한다.

그리디는 매 순간 좋은 선택을 하는 방법

그리디(Greedy)는 지금 단계에서 가장 좋아 보이는 선택을 하고 다음 단계로 넘어가는 알고리즘이야. 예를 들어 여러 회의를 최대한 많이 잡고 싶다면, 가장 빨리 끝나는 회의를 먼저 선택하는 방법을 생각할 수 있어. 빨리 끝나면 남은 시간에 다른 회의를 더 잡을 수 있기 때문이지.

하지만 지금 좋아 보이는 선택이 전체 정답을 보장하는 건 아니야. 그리디는 문제에 맞는 선택 기준이 있고, 그 기준이 전체 최적해를 놓치지 않는다는 이유가 있어야 해. “그냥 큰 것부터 고르면 될 것 같아서”는 증명이 아니야.

대표 패턴 — 회의실을 최대한 많이 배정하기

각 회의는 시작 시간과 종료 시간이 있어. 한 회의가 끝난 뒤에 다음 회의를 시작할 수 있다고 하자. 회의를 최대한 많이 선택하려면 끝나는 시간이 빠른 회의부터 고려하는 전략을 쓸 수 있어. 끝나는 회의를 빨리 마쳐야 나머지 시간을 많이 남기기 때문이야.

Java 예제
Arrays.sort(meetings, (a, b) -> {
    int byEnd = Integer.compare(a[1], b[1]);
    if (byEnd != 0) return byEnd;
    return Integer.compare(a[0], b[0]);
});

int count = 0;
int endTime = 0; // 회의 시작 시간이 0 이상인 문제라고 가정
for (int[] meeting : meetings) {
    int start = meeting[0];
    int end = meeting[1];

    if (start >= endTime) {
        count++;
        endTime = end;
    }
}

정렬이 핵심 첫 단계야. 회의가 끝나는 시간이 빠른 순서로 오도록 만든 뒤, 현재까지 선택한 회의가 끝나기 전 시작하는 회의는 건너뛰어. 시작 시간이 endTime과 같으면 직전 회의가 끝나는 순간 바로 시작할 수 있어. 이 예제는 시작 시간이 0 이상이라 초기 endTime을 0으로 두었어. 음수 시간도 가능한 문제라면 초기값을 별도로 처리해야 해.

동전 거스름돈은 그리디가 항상 맞을까?

한국의 일반적인 500원·100원·50원·10원처럼 큰 단위가 작은 단위의 배수로 이어지는 동전 체계에서는 큰 동전부터 쓰는 그리디가 맞는 경우가 많아. 하지만 어떤 동전 체계든 무조건 맞는 것은 아니야.

예를 들어 동전이 1원, 3원, 4원이고 6원을 만들 때 큰 동전부터 고르면 4+1+1로 3개가 필요하지만, 3+3이면 2개면 돼. 즉, 그리디의 성공 여부는 문제의 구조에 달려 있어.

  • 작은 반례를 직접 만들어 내 선택 기준이 실패하지 않는지 확인했는가?
  • 문제의 입력 조건이 이 전략이 성립하는 전제를 만족하는가?

처음엔 이렇게 설명하는 연습을 하자

“끝나는 시간이 빠른 회의를 먼저 선택한다. 왜냐하면 선택한 회의가 일찍 끝날수록 뒤에 선택할 수 있는 시간이 더 많이 남기 때문이다. 그 다음에는 이미 선택한 회의의 종료 시각 이후에 시작하는 회의 중, 끝나는 시간이 가장 빠른 회의를 선택한다.”

이 정도로 선택 기준과 이유를 문장으로 말할 수 있으면, 단순히 코드를 외우는 것보다 훨씬 튼튼해져.

동적 프로그래밍과 점화식

점화식은 공식을 암기하는 과목이 아니라, 현재 답을 이전의 작은 답으로 설명하는 연습이다.

DP를 어려운 수학이라고 생각하지 말기

DP(동적 프로그래밍)는 이름 때문에 어렵게 느껴지지만, 시작은 이 질문 하나야.

“내가 구하려는 큰 답을, 이미 구할 수 있는 작은 답으로 만들 수 있을까?”

예를 들어 1칸 또는 2칸씩 올라갈 수 있는 계단이 있어. 5번째 칸에 도착하는 방법 수를 구하고 싶어. 5번째 칸에 마지막으로 오려면 4번째 칸에서 한 칸 올라왔거나, 3번째 칸에서 두 칸 올라왔어야 해. 그러면 5번째 칸의 방법 수는 4번째 칸의 방법 수 + 3번째 칸의 방법 수가 돼. 이게 점화식의 시작이야.

먼저 단어부터 번역하자

상태무엇을 계산해 저장할지예: i번째 칸에 도착하는 방법 수
dp[i]i라는 상황의 답을 저장한 칸예: dp[5]는 5번째 칸의 방법 수
점화식현재 답과 이전 답의 관계예: dp[i] = dp[i-1] + dp[i-2]
초기값처음에 알고 있는 답예: dp[1]=1, dp[2]=2
기저 조건더 작은 문제로 쪼개지 않아도 되는 경계예: 1칸과 2칸의 경우 수

점화식이라는 말은 그냥 “앞의 값으로 현재 값을 만드는 규칙”이라고 이해하면 돼. 고급 수학 기호부터 시작하지 않아도 된다.

점화식을 세우는 5단계 — 이 순서대로만 해보기

  1. 1. dp[i]가 무슨 뜻인지 문장으로 정한다. “dp[i]는 i번째 칸까지 도착하는 방법 수”처럼 쓴다. 의미를 정하지 않고 식부터 쓰면 거의 반드시 헷갈린다.
  2. 2. 마지막 순간을 상상한다. i번째 칸에 도착하기 바로 전에는 어디에 있었을까? 한 칸 전 또는 두 칸 전일 수 있다.
  3. 3. 마지막 선택별 경우를 나눈다. i-1에서 한 칸 올라오는 경우와 i-2에서 두 칸 올라오는 경우를 나눈다.
  4. 4. 서로 겹치지 않고 모든 경우를 포함하는지 확인한다. 두 경우는 마지막 이동이 다르므로 한 방법을 두 번 세지 않고, 가능한 마지막 이동을 빠짐없이 포함한다.
  5. 5. 작은 값으로 직접 계산하고 초기값을 정한다. 1칸, 2칸, 3칸 답을 손으로 구한 뒤 식이 맞는지 검산한다.

완전히 숫자로 따라가기: 1칸 또는 2칸씩 올라가기

계단 1칸부터 n칸까지 올라간다고 하자. 한 번에 1칸 또는 2칸만 올라갈 수 있어. 순서가 다른 이동 방법은 서로 다른 방법이야. 예를 들어 3칸을 올라가는 방법은 다음 두 가지 마지막 이동으로 분류돼.

  • 마지막에 1칸 올라왔다면, 직전에 2번째 칸에 있었어. 그 방법 수는 dp[2].
  • 마지막에 2칸 올라왔다면, 직전에 1번째 칸에 있었어. 그 방법 수는 dp[1].

마지막 이동은 반드시 1칸 또는 2칸이야. 그래서 두 경우를 더하면 전체 방법 수가 돼.

Java 예제
// dp[i] = i번째 칸까지 올라가는 방법의 수
// 한 번에 1칸 또는 2칸 이동 가능
int[] dp = new int[n + 1];
dp[1] = 1; // 1칸: [1] 한 가지
if (n >= 2) dp[2] = 2; // 2칸: [1+1], [2] 두 가지

for (int i = 3; i <= n; i++) {
    dp[i] = dp[i - 1] + dp[i - 2];
}

이제 점화식이 외계어가 아니지? dp[i] = dp[i-1] + dp[i-2]는 i번째 칸의 답을 구하려면 이미 계산해 둔 앞의 두 답을 더하면 된다는 뜻일 뿐이야.

DP 코드의 실행 순서를 이해하기

왜 반복문을 작은 칸부터 계산할까? dp[5]를 계산하려면 dp[4]와 dp[3]이 필요해. 그러니까 dp[3], dp[4]가 먼저 채워져 있어야 해. 이처럼 현재 값을 계산할 때 필요한 값이 먼저 계산되도록 순서를 정하는 것이 중요해.

점화식만 맞아도 초기값이 틀리거나 계산 순서가 뒤집히면 결과가 틀릴 수 있어. 코드를 작성한 뒤에는 작은 n=1, n=2, n=3을 직접 대입해 보자.

DP는 항상 “방법 수”만 구할까? 아니야. 최소·최대도 구한다

DP는 답을 저장하는 방식이고, 저장하는 답은 문제에 따라 달라. 어떤 곳까지 가는 최소 비용을 구할 수도 있고, 선택할 수 있는 점수의 최댓값을 구할 수도 있어. 먼저 dp[i]의 뜻을 명확히 정해야 해.

예를 들어 각 칸에 비용이 있고, 시작점에서 i번째 칸까지 가는 최소 비용을 구하며 한 번에 한 칸 또는 두 칸 갈 수 있다고 해 보자. 마지막에 i에 도착하려면 i-1 또는 i-2에서 왔을 테니 두 비용 중 작은 것을 고르면 돼. 단, 현재 칸 비용도 더해야 해.

Java 예제
// cost[i] = i번째 칸에 들어가는 비용
// dp[i] = i번째 칸까지 오는 최소 비용
// cost[i] = i번 칸에 도착할 때 내는 비용
// dp[i] = 0번 칸에서 i번 칸까지 도착하는 최소 비용
// 0번 칸에서 시작하며, 1칸 또는 2칸 이동할 수 있다고 가정
int[] dp = new int[n];
dp[0] = cost[0];
if (n >= 2) {
    dp[1] = cost[1] + dp[0];
}
for (int i = 2; i < n; i++) {
    dp[i] = cost[i] + Math.min(dp[i - 1], dp[i - 2]);
}

전제: 이 코드는 배열의 0번 칸에서 시작하고, 각 칸에 도착할 때 cost를 내며, 한 번에 1칸 또는 2칸 이동한다고 가정해. 실제 문제에서는 출발점 비용과 이동 규칙이 다를 수 있으니, 먼저 dp[i]의 뜻과 출발 조건을 문제에 맞춰 정해야 한다.

문제를 풀 때 이 빈칸을 실제로 채워 봐. 처음엔 10분 이상 걸려도 정상이다. 점화식은 타고난 수학 머리가 아니라, 현재 상태의 의미와 마지막 선택을 정리하는 훈련으로 익힌다.

이건 패턴의 방향을 잡기 위한 분류야. 모든 경우의 수가 무조건 더하기 한 번으로 끝나거나, 모든 최솟값 문제가 똑같은 식을 쓰는 것은 아니야.

DP에서 초보자가 가장 많이 하는 실수

  • dp[i]의 뜻을 정의하지 않음. 의미가 없으면 식을 만들 기준도 없다.
  • 점화식을 외우고 문제에 무조건 적용함. 예전에 본 식과 지금 문제의 상태가 같은지 확인해야 한다.
  • 초기값 누락. dp[0], dp[1]은 반복문이 계산하지 않으므로 직접 정해야 할 수 있다.
  • 배열 인덱스 착각. n칸이 0~n-1인지, 1~n으로 정의했는지 정리한다.
  • 작은 값으로 검산하지 않음. n=1, 2, 3에서 손으로 푼 결과와 코드 결과를 비교한다.
  • 정수 범위 확인 안 함. 경우의 수가 급격히 커지면 int 범위를 넘을 수 있어 long이나 나머지 연산이 필요할 수 있다.
직접 생각해 보기: dp[i]를 “i번째 칸까지 도착하는 방법의 수”라고 정했다. 마지막에 i-1에서 한 칸 오거나 i-2에서 두 칸 오는 것이 전부라면 점화식은?
답

dp[i] = dp[i - 1] + dp[i - 2]

왜?

마지막 이동이 1칸인 방법과 2칸인 방법은 서로 겹치지 않고, 가능한 마지막 이동을 모두 포함한다. 각 그룹의 방법 수를 더하면 전체 방법 수다.
